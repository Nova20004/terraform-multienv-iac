Multi-environment infrastructure, runnable on a laptop. Docker is the cloud. Postgres is the state backend. Ansible is the configuration layer. No AWS, GCP or Azure account, and no paid service.

`prod` in this repository is **not** high availability. It is three containers and one database on a single Docker host.

```text
dev / staging / prod
        |
        v
+--------------------------------------+
| Postgres 17  (bootstrap/, local state)|
| backend "pg" + advisory locks        |
| one database per environment         |
+--------------------------------------+
        |
        v
+------------+   +------------------+   +-------------------+
| network    |   | compute          |   | database          |
| frontend   |-->| N systemd nodes  |   | Postgres 17       |
| backend    |   | SSH on 127.0.0.1 |   | internal network  |
| (internal) |   | optional nginx LB|   | no published port |
+------------+   +------------------+   +-------------------+
                          |
                          v
              ansible/inventories/<env>/hosts.ini
                          |
                          v
              common -> nginx -> app -> smoke
              (/health, pg_isready on the backend network)
```

## AWS concept to local equivalent

| AWS | This repo |
|---|---|
| Account / region | One Docker daemon (`docker_host`, default from `DOCKER_HOST`) |
| S3 state + DynamoDB lock | Postgres `backend "pg"` and session advisory locks |
| VPC + public subnet | `frontend` bridge |
| Private subnet | `backend` bridge with `internal = true` |
| EC2 | systemd container built from `docker/node` |
| ALB | nginx container (`enable_lb`) |
| RDS | Postgres container, no published port |
| Tags | Docker labels `environment`, `managed-by=terraform`, `project`, `owner` |
| Security group "no ingress" | No `ports` block, plus the internal network |
| IAM / SSM | SSH as `ansible`, key injected at start, never baked into the image |

## Environments

| | dev | staging | prod |
|---|---|---|---|
| Nodes | 1 | 2 | 3 |
| Node memory | 512 MB | 768 MB | 1024 MB |
| CPU shares | 256 | 512 | 1024 |
| Load balancer | off | `127.0.0.1:8080` | `127.0.0.1:8081` |
| SSH ports | 2201 | 2301–2302 | 2401–2403 |
| Frontend CIDR | `10.10.0.0/24` | `10.20.0.0/24` | `10.30.0.0/24` |
| Backend CIDR | `10.10.1.0/24` | `10.20.1.0/24` | `10.30.1.0/24` |
| DB memory | 256 MB | 512 MB | 1024 MB |
| Backup retention | 1 day | 7 days | 30 days |
| Restart | `on-failure` | `on-failure` | `unless-stopped` |
| State database | `terraform_state_dev` | `terraform_state_staging` | `terraform_state_prod` |

CIDRs are inside `10.0.0.0/8` so they do not collide with Docker's default `172.17.0.0/16` bridge or the `192.168.0.0/16` range Docker Desktop often uses. The three environments can run side by side.

## What this repo demonstrates

- Three environments sharing modules, with separate state databases so their locks do not collide.
- A Postgres remote backend on the laptop, with advisory locks and no cloud account.
- An Ansible inventory generated by Terraform, then an idempotent configure and a smoke test.
- Pinned GitHub Actions, TFLint, Trivy and ansible-lint, with no paid provider.

## Quickstart

Prerequisites: Docker, Terraform `>= 1.8` (CI pins `1.17.2`), Python 3.12 or 3.13, `make`, OpenSSH.

### macOS

`/usr/bin/make` does nothing until the Command Line Tools are installed. GNU make is enough: `brew install make`, then `gmake` (or put `$(brew --prefix make)/libexec/gnubin` on `PATH`). The Docker provider does not read `docker context`. When `DOCKER_HOST` is unset, `make` exports the socket from `docker context inspect`. That covers Docker Desktop, which often has no `/var/run/docker.sock`.

1. Create a virtualenv and install Ansible:

   ```bash
   python3 -m venv .venv
   . .venv/bin/activate
   python -m pip install -r ansible/requirements.txt
   ```

2. Generate `.env`. This writes a random password on both lines and leaves the port at `55432`. It does not overwrite an existing `.env`.

   ```bash
   make env
   ```

3. Build the state database, the dev environment, and run the smoke tests. About 2 minutes once the images are local. The first run is longer: it builds the node image and installs packages.

   ```bash
   make demo
   ```

The end of a successful run looks like this:

```text
TASK [app : Report the smoke-test result] **************************************
ok: [lab-dev-node-1] => {
    "msg": "Smoke test passed on lab-dev-node-1: /health returned 200 and Postgres at lab-dev-db:5432 is accepting connections."
}

PLAY RECAP *********************************************************************
lab-dev-node-1             : ok=5    changed=0    unreachable=0    failed=0
```

## Try it

Dev has no load balancer. The health check is on the node, reached through SSH:

```bash
ssh -p 2201 -i .ssh/id_ed25519 -o StrictHostKeyChecking=accept-new ansible@127.0.0.1 curl -fsS http://127.0.0.1/health
```

Staging publishes nginx on the host. Deploy it, then:

```bash
make deploy ENV=staging
curl -fsS http://127.0.0.1:8080/health
```

When you are done:

```bash
make destroy ENV=dev
make bootstrap-destroy CONFIRM=yes
```

`make bootstrap-destroy` deletes the state volume. Destroy every environment first or the state of staging and prod goes with it.

Other targets: `make help`.

## Company adaptation guide

Fork the repo. Change data, not structure.

1. Set `project` and `owner` in each `environments/*/terraform.tfvars` (start from the `.example` files). Names must match the validation rules: short lowercase project, owner up to 63 characters.
2. Pick CIDRs still inside `10.0.0.0/8` and still unique per environment. The validation rejects `172.16.0.0/12` and `192.168.0.0/16`.
3. Move `ssh_port_base` and `lb_port` off anything already bound on the laptop. Ports are published on `127.0.0.1` only.
4. Point `ssh_private_key_path` at a company key, or keep `make ssh-key` (it writes a dedicated key under `.ssh/`, which is gitignored). Only the `.pub` file is passed into the container, as `SSH_PUBLIC_KEY`, at start. Ansible records host keys in `.ssh/known_hosts`. `make configure` forgets the keys for this inventory's localhost ports first, because a recreated container presents a new host key and `accept-new` will not replace one.
5. Leave `docker_host` null unless you want to pin a socket. `make` fills `DOCKER_HOST` from the active Docker context when it is empty. Colima, rootless, and remote engines work the same way.
6. Replace image digests in `terraform.tfvars` when you patch Ubuntu, Postgres or nginx. The variables reject `:latest` and a floating `postgres:17` tag.
7. For a shared Postgres instead of the laptop container, set `STATE_DB_HOST`, `STATE_DB_PORT`, `STATE_DB_USER` and `STATE_DB_SSLMODE=require` (or `verify-full`) in `.env`. `make` builds `PG_CONN_STR` from those values. `sslmode=disable` is only acceptable for the bootstrap container bound to `127.0.0.1`. Create `terraform_state_dev`, `terraform_state_staging` and `terraform_state_prod` on that server.
8. Size `node_count`, memory, CPU shares, `restart_policy` and `backup_retention_days` per environment. Run `scripts/backup-db.sh` from cron if you want the retention to actually happen; nothing uploads dumps off the machine.
9. Keep `.env` out of git. CI generates it at runtime. Do not commit `backend.hcl`, `*.tfvars`, plans, or generated inventories.

## State locking and security

Each environment stores state in its own Postgres database (`terraform_state_dev`, `terraform_state_staging`, `terraform_state_prod`), so a dev operation and a staging operation do not block each other. Two operations in the same environment do. Locks end when that Terraform process disconnects. `terraform force-unlock` is not available. `make locks` shows the current database. Details, the password, and the loopback binding are in [docs/STATE-LOCKING.md](docs/STATE-LOCKING.md).

There is no Docker-in-Docker role. Mounting the host socket into a container needs more privilege than this lab takes.

## Ansible

Roles: `common`, `nginx`, `app`. Fully qualified module names, handlers, tags. `command` tasks set `changed_when`.

`common` installs unattended-upgrades, creates the sudo user, drops an sshd config (`PermitRootLogin no`, `PasswordAuthentication no`) and runs `sshd -t` before the restart handler, and installs a fail2ban sshd jail.

`common_skip_kernel_tasks_when_docker` (default `true`) skips sysctl, ufw and chrony when `ansible_virtualization_type == 'docker'`. Those tasks run on a real VM. The generated inventory sets the variables explicitly. Set the skip flag to `false` only on a host with its own kernel.

`nginx` serves the app and proxies `/health`. `app` is a systemd unit bound to `127.0.0.1:8080`, installs `postgresql-client`, and the `smoke` tag checks `/health` (with retries) and `pg_isready` from the node to the database over the backend network.

`ansible.cfg` sets `StrictHostKeyChecking=accept-new`.

## Limitations

- Prod is one Docker host, one database container, one volume, and an nginx container. `unless-stopped` is a restart policy, not failover.
- systemd in a container is a lab stand-in, and it runs as root. `.trivyignore` accepts `DS-0002` for that single Dockerfile. On Docker Desktop 29.9.2 (cgroup v2) the nodes boot **without** `--privileged`, using `cgroupns=host`, a `/sys/fs/cgroup` bind, tmpfs on `/run`, `/run/lock` and `/tmp`, and `NET_ADMIN`. If your daemon cannot do that, set `systemd_privileged = true`. That flag is lab-only. Do not copy it into a cloud VM module.
- sysctl, ufw and chrony do not run inside these containers. The skip is intentional.
- The application database has no replica and no point-in-time recovery. `scripts/backup-db.sh` is a `pg_dump` with a retention window.

## Porting to a cloud

Keep the environment roots, the Ansible roles, and the inventory contract (`ansible_host`, `ansible_port`, `ansible_user`, key path, `db_host`). Swap the modules:

| Module | Replace with |
|---|---|
| `modules/network` | VPC, subnets, route tables. Map `frontend` to a public subnet and `backend` to a private one. |
| `modules/compute` | VMs or an instance group, plus a real load balancer. Drop `cgroupns_mode`, tmpfs, `NET_ADMIN` and `systemd_privileged`. Publish SSH through a bastion, not `127.0.0.1`. |
| `modules/database` | Managed Postgres. Keep `random_password` and the same outputs so the inventory and `pg_isready` check do not change. |
| `bootstrap/` + `backend "pg"` | `backend "s3"` (or GCS / Azure RM) with that backend's lock table. Delete the laptop Postgres. |
| Ansible `common` | Leave it. Set `common_skip_kernel_tasks_when_docker` to `false` so sysctl, ufw and chrony run. |

Do not port the node Dockerfile. It exists so systemd and sshd run under Docker.

## Layout

```text
bootstrap/                 Postgres state database (local state, one-time)
docker/node/               Ubuntu 24.04 + systemd + sshd image
modules/network/           frontend + internal backend
modules/compute/           nodes and optional nginx load balancer
modules/database/          Postgres on the backend network
environments/{dev,staging,prod}/
ansible/                   roles, ansible.cfg, generated inventories
scripts/                   verify-lock, verify-isolation, backup-db
docs/                      VERSIONS.md, STATE-LOCKING.md
.github/workflows/iac-ci.yml
```

`scripts/verify-lock.sh` checks two things: two plans in one environment conflict, and a dev plan plus a staging plan do not. It is not part of CI. `scripts/verify-isolation.sh` checks that the application database has no host port, is closed from the host, and accepts TCP from a node.
